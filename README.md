# Alaxee Proxy

一个面向 Microsoft Edge 的轻量级 Manifest V3 代理扩展。它把 Edge 的浏览器代理指向**你自己填的一个 HTTP 或 SOCKS5 服务器**，并按域名决定哪些网站直连、哪些强制走代理。

它不提供代理节点、不管理订阅、不判断你的代理软件是否在运行，也**不针对任何特定代理软件**——Clash/mihomo、sing-box、v2ray、公司内网的 HTTP 代理、`ssh -D` 隧道，对扩展来说都只是「一个地址加一个端口」。

## 当前版本

- 版本：`0.1.3`
- 目标浏览器：Microsoft Edge（Chromium，Manifest V3）
- 发布方式：Microsoft Edge Add-ons（计划上架）；开发期间也可本地加载解压缩版本
- 运行依赖：无第三方 JavaScript 运行时依赖

## 功能

- **走代理服务器**：使用你填写的地址、端口和协议（SOCKS5 或 HTTP）。
- **直接连接**：让 Edge 不使用浏览器代理，黑名单是例外。
- **当前网站规则**：从当前标签页一键加入直连白名单，或加入强制走代理的黑名单。
- **本机地址直连**：`localhost`、`127.0.0.1`、`::1`、`*.local` 和不带点的主机名默认直连，避免本地开发服务器和路由器管理页被送去代理。可用一个开关关闭。
- **规则列表**：支持按域名搜索、按「最近添加 / 域名」排序，并标出当前网站命中的那一条。
- **快速填地址**：直接粘贴 `127.0.0.1:7890` / `socks5://host:port` 即可，也可以从常见端口里点一个作为起点。
- **备份与恢复**：导出全部设置和规则为 JSON，重装或换电脑时恢复。导入前会先告诉你将替换什么。
- **子域名选项**：白名单和黑名单均可选择仅当前主机名，或同时匹配主域名及其子域名。
- **规则优先级**：代理黑名单优先于白名单；黑名单用于覆盖上级白名单的例外域名。
- **逐标签页状态图标**：工具栏按当前网页实际的浏览器路由显示 XEE 状态图形：交给代理、浏览器直连（包括白名单与本机地址）或状态未知。首次点击「加入直连白名单」时会请求可选的 `tabs` 权限；允许后，所有标签页自动按网址更新图标。未授权时工具栏显示“未知”，不会拿全局模式冒充当前网页状态。也可以在面板中单独启用。
- **二级菜单**：将概览与域名规则分开，规则页面再切换直连白名单和代理黑名单，避免主界面无限增长。
- **本地持久化**：代理地址、协议、模式、白名单和黑名单保存在 `chrome.storage.local`，当前版本仍为本地模式，没有云端同步或遥测。
- **完整设置中心**：复用快捷面板的同一套交互与控制逻辑，提供更宽的页面布局；两者不会维护两份独立配置。

## 和你的代理软件是什么关系

**扩展只做浏览器这一层。** 它把 Edge 的浏览器代理设置指向你填写的地址，然后由**那个程序**决定流量接下来怎么走。扩展不读取、不修改、也不关心它的配置。

这意味着：

- 换一个代理软件、换一个端口，扩展只需要改一处地址，不需要升级。
- 你在代理软件里的分流规则、节点选择、TUN 开关，扩展完全看不到，也不做判断。
- 「走代理服务器」不等于「一定用到了某个节点」。代理软件选中 DIRECT 时，请求虽然交给了它，最终还是直连。

不知道填哪个端口时，面板里列了 8 个常见端口作为参考，并且有「填了端口但不生效？」的排障清单。**最容易错的是填了控制面板端口**——Clash 的 9090 是 REST API，不转发流量。

地址和端口因软件而异：Clash/mihomo 通常是 Mixed 端口（默认 `7890`，SOCKS5 与 HTTP 都能用），v2ray 常见 `10808`/`10809`，`ssh -D 1080` 就是 `1080`。**默认值是空的**，首次使用必须自己填——扩展不会替你猜。

### 规则优先级

域名规则由 Chromium PAC 脚本在浏览器代理层执行，从强到弱：

1. **代理黑名单**（显式强制）：命中就走代理，连本机地址也不例外。
2. **本机地址**：`localhost`、`127.0.0.1`、`::1`、`*.local`、不带点的主机名 → 直连。
3. **直连白名单**（显式直连）：命中就绕过代理。
4. **默认路由**：「走代理服务器」模式下走代理，「直接连接」模式下直连。

内网 IP（`192.168.x.x`、`10.x.x.x`、`172.16–31.x.x`）**不在**本机直连范围内，因为公司代理往往正是访问内网的唯一通道；需要时把它们加进直连白名单。

启用「包含子域名」时，规则会匹配 `example.com` 及其子域名。两类规则重叠时黑名单优先，因此可以用 `api.example.com` 的黑名单覆盖 `example.com` 的宽泛白名单。

**注意：** 如果代理软件同时启用了 TUN、系统透明代理或其他网络接管方式，浏览器的 DIRECT 不一定意味着数据包完全绕过它——TUN 在网络层接管流量，浏览器设成直连也照样会进入 TUN。这时切换扩展的模式不会有可见效果，那是预期行为，不是故障。

## 本地安装到 Edge

1. 解压发布包到固定目录，例如 `C:\AData\Projects\Alaxee-Proxy`。
2. 在 Edge 地址栏打开 `edge://extensions`。
3. 打开 **开发人员模式**。
4. 点击 **加载解压缩的扩展**。
5. 选择能直接看到 `manifest.json` 的项目文件夹。
6. 将 Alaxee Proxy 固定到工具栏。
7. 点击扩展图标打开快捷面板；先填好代理服务器地址和端口并保存，然后可以切换路由、管理当前网站规则。
8. 点击面板右上角「设置」打开完整设置中心。完整设置与快捷面板共用同一套代理模式、连接和白/黑名单控制，不会出现两个页面功能不一致。

## 权限说明

| 权限 | 用途 |
| --- | --- |
| `proxy` | 设置 Edge 浏览器代理模式、PAC 域名路由及代理例外。 |
| `storage` | 本地保存设置和直连白名单。 |
| `activeTab` | 用户点击扩展时读取当前标签页 URL，以便快捷添加当前网站；不申请全站内容访问权限。 |
| `tabs`（可选） | 用户首次添加直连白名单时会请求，或可在面板中主动启用。授权后读取标签页 URL，并按每个页面的实际浏览器路由更新工具栏图标和悬停标题；未授权时显示未知状态；仅本地处理，不读取页面内容、不上传数据。 |

扩展不申请 `webRequest`、`host_permissions`、剪贴板、账户或网络访问权限；`tabs` 仅作为可选权限，由用户在快捷面板中主动开启。没有远程脚本、遥测或后台服务器。

## 开发与测试

要求 Node.js 20+ 和 Python 3。无需安装 npm 依赖。

```bash
npm test
npm run check
python -m json.tool manifest.json > /dev/null
npm run package:extension
```

`npm run package:extension` 会在 `dist/` 生成仅包含扩展运行文件的商店 ZIP，不会把测试、文档和 Git 元数据打进商店包。

商店包的文件清单不再手工维护。`scripts/runtime-files.mjs` 从 `manifest.json` 出发，沿 ES module import、HTML 引用和图标字面量推导出运行文件闭包，`scripts/package-extension.py` 直接使用该闭包，并在打包后重新读取 ZIP 校验文件集合。因此：

- 新增模块只要被现有代码 import，就会自动进包，不会出现「构建成功但文件缺失」；
- 引用不存在的文件、或引入未打包的裸 import（npm 依赖）时，打包会直接失败并列出具体路径；
- 打包脚本需要 Node.js 20+ 与 Python 3 同时可用，因为闭包由 Node 计算。

## 发布和自动更新

- 初次上架：必须在 Microsoft Partner Center 创建 Edge Add-ons 产品、填写商店信息和隐私/权限声明，并提交首次审核。
- 商店用户更新：首次发布后，Edge 通过商店机制自动向用户提供审核通过的更新。
- 开发者自动发布：项目包含 GitHub Actions。首次上架完成、启用 Edge Add-ons Publish API 并在仓库配置密钥后，推送匹配版本的 `vX.Y.Z` 标签会自动运行测试、构建商店 ZIP，并将新包提交给 Microsoft 审核。
- 自动化提交不等于审核通过或立即上架；Microsoft 仍控制认证和发布时间。

完整步骤见 [`docs/EDGE-ADDONS-PUBLISHING.md`](docs/EDGE-ADDONS-PUBLISHING.md)。商店列表草稿见 [`STORE-LISTING.md`](STORE-LISTING.md)，隐私说明见 [`PRIVACY.md`](PRIVACY.md)。

## 已知边界

- 代理设置是 **Edge 配置级别** 的，不是只作用于当前标签页。
- 加入白名单会影响 Edge 中访问该主机名的所有标签页和请求，而不只是添加时所在的标签页。
- 首次安装没有预填任何地址；在填写之前，「走代理服务器」模式不会生效，「直接连接」模式仍然可用。
- `edge://`、扩展商店等受限页面、`file://` 本地文件不能加入当前网站白名单；这类页面显示未知状态图形。
- 未启用可选 `tabs` 权限前，工具栏显示未知状态，不会把全局模式冒充成当前网页路由。允许后，工具栏按每个标签页的白名单、黑名单和全局模式分别更新。
- 扩展不能判断代理程序是否存活，也不做健康检查。状态显示的是**浏览器当前的代理配置**，不是对面服务端的状态。
- 其他代理扩展、组织策略或浏览器管理策略可能占用代理设置控制权。若出现冲突，应关闭其他代理扩展或检查管理策略。
- 当前版本不支持代理认证账号密码、PAC 手写规则、订阅导入、分应用代理和云同步。
- 已移除「跟随系统代理」模式：它会让白名单和黑名单静默失效，而界面上规则却还在。从 0.1.x 升级时会自动迁移并提示。

## 安全原则

- 只连接用户自行配置的代理地址。
- 默认地址留空、由用户填写；示例用 loopback，不要求任何代理软件开启 LAN 访问。
- 不读取代理订阅、不收集浏览记录、不上传白名单。
- 不使用远程代码或动态代码执行。
- Edge Add-ons API 凭据必须保存在 GitHub Actions Secrets，不能提交到代码仓库。
