# Icons

Two different kinds of asset live here, and they are maintained differently.

## `status/` — generated

`status/{proxy,direct,forced,unknown}{16,32}.png` are the toolbar states. They are
**generated**, not hand-drawn: `python3 scripts/render-icons.py` draws them from
the same crescent-and-star geometry the popup header uses, and
`python3 scripts/render-icons.py --check` (part of `npm run check`) fails if a
committed file differs from what the script would produce.

The four states share one silhouette and differ only in colour. That is deliberate:
the brand kit ships four time-of-day icons, but their measured average colours
(`#edb0c0` / `#eaacbd` / `#f5c5cf` / `#8d6683`) are not separable at 16px, so they
cannot encode a routing state.

## `icon{16,32,48,128}.png` — taken from the kit

These are the extension's own icon, shown in the browser's extension list and in
the store listing. They are the brand kit's `icon-day-small-*` and `icon-day-128`
files copied verbatim.

They are **not** generated by `scripts/render-icons.py` and should not be: the kit
artwork is a layered illustration (moon, star, cloud bank, horizon glow) that a
few hundred lines of standard-library rasterising would approximate poorly. Copy
replacements from `alaxee-kit/brand/icons/png/` when the kit is updated, and keep
these four sizes in step with `manifest.json`.

`tests/brand.test.js` checks that each file is a structurally valid PNG at the
size its name promises, so a hand-copied file of the wrong size fails the build
rather than showing up stretched in the store.
