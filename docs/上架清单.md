## 第六步：Privacy（**审核最容易卡在这**）

左侧 **Privacy**。五个部分，文案都在下面，**直接复制粘贴**。

### 6.1 Single Purpose

```
Alaxee Proxy only configures Microsoft Edge's built-in browser proxy setting,
so the user can point the browser at a proxy endpoint they already run, and
switch between that endpoint and a direct connection.
```

### 6.2 Permission justification

页面会按 manifest 自动列出四项，每项一个框：

**`proxy`**
```
Sets Edge's browser-level proxy configuration, including the PAC script that
implements the domain rules. Without it the extension cannot do anything.
```

**`storage`**
```
Saves the user's proxy endpoint and domain rules locally, and optionally in the
browser's own sync storage when the user turns cross-device sync on.
```

**`activeTab`**
```
Reads the hostname of the active page, only after the user clicks the toolbar
button, to show which rule matches and to offer a one-click bypass.
```

**`tabs`（可选权限）**
```
Requested at runtime only if the user enables per-tab toolbar status. Reads tab
URLs locally to select the matching state icon; never reads page contents.
```

### 6.3 Are you using remote code?

选 **No, I am not using remote code**。

### 6.4 Data usage

- **What user data do you plan to collect...** → **全部不勾**
- **I certify that the following disclosures are true** → **全部勾上**

### 6.5 Privacy policy URL

```
https://github.com/alaxeecc/Alaxee-proxy/blob/main/PRIVACY.md
```

### Description 复制这段

```
Alaxee Proxy is a small, local-only proxy control panel for Microsoft Edge. It
points Edge's browser proxy at a listener you already run - any HTTP or SOCKS5
endpoint, such as Clash/mihomo, sing-box, v2ray, a corporate HTTP proxy, or an
SSH tunnel. It does not provide proxy servers, nodes, subscriptions, or VPN
service, and it does not integrate with any particular proxy application.

Features:
- Switch Edge between your configured proxy server and direct connection.
- Configure the proxy protocol, address, and port.
- Local addresses (localhost, 127.0.0.1, ::1, *.local) always connect directly,
  so local dev servers keep working.
- Search and sort the domain rule lists, and see which rule matches the current
  page.
- Add the current website to a direct-connection bypass list from the toolbar
  popup.
- Choose whether a bypass entry applies only to the hostname or also to its
  subdomains.
- Keep settings locally in Edge; no account or cloud service is required.
- Back up and restore the whole configuration as a local JSON file.
- Optionally sync settings and rules across the user's own devices through the
  browser's built-in sync storage. Off by default.

The extension does not read or change any proxy application's configuration.
Websites not in the direct list continue through the configured listener, where
that program's own rules decide how to route them. The extension reports what
the browser is configured to do; it does not health-check the listener.
```

## 第八步：提交认证

1. 回 **Store listings**，确认 **Status** 那列显示 **Complete**
2. 右上角 **Publish** 变成可点（灰的话说明还有必填项）
3. 点 **Publish**
4. **Notes for certification** 里粘贴下面这段
5. 再点一次 **Publish**

```
This extension only sets Edge's own browser proxy configuration. It ships with
no proxy server, no nodes, no subscriptions, and provides no VPN service.

The proxy address field is empty on first install. Nothing is proxied until the
user types in an endpoint they already run themselves. To test: open the popup,
leave the address empty, and confirm the page still loads normally.

The proxy permission is used only for chrome.proxy.settings and for building the
PAC script from the user's own domain rules. No page content is read. Tab URLs
are read only after the user clicks the toolbar button, and only to display
which rule matches the current host. Nothing is transmitted anywhere; there is
no backend server and no telemetry.

There are no test accounts because there is no account system.
```

⬜ 已提交，状态变成审核中

**等 1–7 个工作日。** 通过后状态变 **In the Store**，商店上线。

## 第九步（上线之后再做）：配置自动发布

**上架前不用管这步。** 只有上线后才能配 API。

1. Partner Center → 你的扩展 → **Publish API**
2. 启用 **new API experience** → **Create API credentials**
3. 记下 **Client ID** 和 **API Key**（**Key 只显示一次**）
4. 回 **Extension overview** 复制 **Product ID**
5. GitHub 仓库 → Settings → Secrets and variables → Actions → 加三条：
   - `EDGE_ADDONS_PRODUCT_ID`
   - `EDGE_ADDONS_CLIENT_ID`
   - `EDGE_ADDONS_API_KEY`

⬜ 三条 secret 都加好

⚠️ API Key 约 **72 天过期**，到期后发布报 401，重新生成再更新 secret。

## 以后每次更新

```bash
# 1. manifest.json 和 package.json 的 version 都改（必须一致）
# 2. npm test && npm run check
# 3. git add -A && git commit -m "..." && git push origin main
# 4. git tag v0.2.1 && git push origin v0.2.1
```

**第 4 步之后全自动**：Actions 打包 → 上传微软 → 提交认证。

# 三个常见卡点

**1. Publish 按钮是灰的**
说明有必填项没填。回 **Store listings** 看哪一行的 Status 还不是 **Complete**。最常见是 Description 没到 250 字符，或者 Logo 没传。

**2. 点 Publish 报 `Something went wrong. correlationId : undefined`**
微软自己的老问题，不是你的包有错。清 cookie 和缓存，或者换 InPrivate 窗口重试。

**3. 审核被打回**
代理类扩展常见。看驳回理由：
- 说权限说明不清 → 把 6.2 那四段写得更具体
- 说不知道是干什么的 → 补认证备注，强调「不提供代理服务器、不自带节点」

改完不用重新创建产品，重新上传包并再次提交即可。
